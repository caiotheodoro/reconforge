# ISO 20022 Messages for Reconciliation

Status: RESEARCH-ONLY corpus. Inline source URLs; uncertain claims marked
**UNVERIFIED**.

## 1. What ISO 20022 is

- ISO 20022 is the ISO standard for electronic data interchange between
  financial institutions — a metadata repository plus XML (and ASN.1) message
  syntax. It is the successor to ISO 15022 (which succeeded ISO 7775).
  Source: https://en.wikipedia.org/wiki/ISO_20022
- SWIFT is the ISO 20022 Registration Authority.
  Source: https://en.wikipedia.org/wiki/ISO_20022
- Message family prefixes relevant to reconciliation:
  `pacs.*` = Payments Clearing and Settlement, `camt.*` = Cash Management,
  `pain.*` = Payments Initiation.
  Source: https://de.wikipedia.org/wiki/SWIFT-Nachricht
- Message names embed a version, e.g. camt.053.001.08 = 8th version of "Bank to
  Customer Statement"; SEPA initially used .001.02, newer implementations .001.08+.
  Source: https://de.wikipedia.org/wiki/Camt-Format

## 2. The four messages ReconForge cares about

### pacs.008 — FIToFICustomerCreditTransfer
- **Definition**: FI-to-FI Customer Credit Transfer — the interbank customer
  credit transfer; the ISO 20022 replacement for the MT103 family of customer
  payments in cross-border (CBPR+) and in SEPA (pacs.008.001.02 is the SCT
  interbank message).
  Sources: https://www.paiementor.com/cbpr-plus-iso-20022-migration/ ;
  https://www.paiementor.com/sepa-payments-schemes-instruments/
- **Relation to MT**: counterpart/implementation of MT103 (single customer
  credit transfer). CBPR+ replaces "legacy MT formats" with pacs.008 and
  pacs.009; after the migration, MT103/MT202 will no longer be exchanged over
  the SWIFT network for these flows.
  Source: https://www.paiementor.com/cbpr-plus-iso-20022-migration/
- **Key elements** (ISO 20022 message definition repo — element-level detail
  treated as VERIFIED by standard, not re-fetched field-by-field):
  - GrpHdr (group header): MsgId, CreDtTm, NbOfTxs, SttlmInf (SettlementInformation)
  - PmtId (payment identification): **InstrId** (instruction identification),
    **EndToEndId** (end-to-end reference — survives the whole chain),
    TxId, UETR (unique end-to-end transaction reference, Block-3 in MT)
  - PmtTpInf, IntrBkSttlmAmt (interbank settlement amount), IntrBkSttlmDt,
    **ValDt** (value date), FctvDt
  - Dbtr/DbtrAcct, DbtrAgt, Cdtr/CdtrAcct, CdtrAgt
  Source: https://www.iso20022.org/iso-20022-message-definitions
  (official repo; element presence there is the citation)
- EndToEndId is also confirmed as a structured element in the camt reporting
  family used to auto-match payments to open items.
  Source: https://de.wikipedia.org/wiki/Camt-Format

### pacs.009 — FinancialInstitutionCreditTransfer
- **Definition**: FI-to-FI credit transfer — the bank-to-bank transfer; the
  ISO 20022 counterpart of MT202 (including the MT202 COV pattern for covers:
  pacs.009 with cover; element-level cover mechanics **UNVERIFIED**).
  Source: https://www.paiementor.com/cbpr-plus-iso-20022-migration/
- **Key elements**: same header/payment-id family as pacs.008 (InstrId,
  EndToEndId, IntrBkSttlmAmt, ValDt), with DbtrAgt/CdtrAgt being banks.
  Source: https://www.iso20022.org/iso-20022-message-definitions

### camt.053 — BankToCustomerStatement
- **Definition**: end-of-day statement with booked entries and closing
  balances; replaces **MT940**.
  Sources: https://de.wikipedia.org/wiki/Camt-Format ;
  https://en.wikipedia.org/wiki/MT940
- **Key elements**: Stmt/StmtId, Acct, Bal (balances with Tp/Dt/Amt), Ntry
  (entries: Amt, CdtDbtInd, ValDt, BookgDt, NtryRef, BkTxCd, TxDtls with
  PmtId/EndToEndId, InstrId, Dbtr/Cdtr). Element presence per the official
  message definition.
  Source: https://www.iso20022.org/iso-20022-message-definitions
- In SEPA, camt formats have been mandatory for account reporting since 2014.
  Source: https://de.wikipedia.org/wiki/Camt-Format

### camt.054 — BankToCustomerDebitCreditNotification
- **Definition**: single debit/credit booking notifications; replaces
  **MT900/MT910**.
  Source: https://de.wikipedia.org/wiki/Camt-Format
- **Key elements**: Ntfctn (notification) with Ntry (entry) carrying Amt,
  CdtDbtInd, ValDt, BookgDt, and TxDtls (PmtId/EndToEndId, Dbtr/Cdtr, RmtInf).
  Source: https://www.iso20022.org/iso-20022-message-definitions

### Related messages in the ecosystem
- camt.052 (BankToCustomerAccountReport) replaces MT942 (intraday).
- camt.056 (FIToFIPaymentCancellationRequest) and camt.029 (ResolutionOfInvestigation)
  support the return/cancel/investigation workflow used in exception handling.
  Source: https://de.wikipedia.org/wiki/Camt-Format ;
  https://www.paiementor.com/sepa-payments-schemes-instruments/

## 3. MT → ISO 20022 mapping table

| MT | ISO 20022 | Role |
|---|---|---|
| MT103 (single customer credit transfer) | **pacs.008** FIToFICustomerCreditTransfer | customer payment |
| MT202 / MT202 COV (FI transfer / cover) | **pacs.009** FinancialInstitutionCreditTransfer (incl. cover variant) | bank-to-bank / cover |
| MT940 (customer statement, EOD) | **camt.053** BankToCustomerStatement | statement |
| MT900 / MT910 (debit/credit confirmation) | **camt.054** BankToCustomerDebitCreditNotification | booking notification |
| MT942 (intraday report) | **camt.052** BankToCustomerAccountReport | interim report |
| MT101 (customer request) | pain.001 | initiation |

Sources: https://de.wikipedia.org/wiki/Camt-Format ;
https://www.paiementor.com/cbpr-plus-iso-20022-migration/ ;
https://www.paiementor.com/sepa-payments-schemes-instruments/

## 4. Migration timeline (CBPR+, cross-border)

- March 2023: coexistence phase (MT and ISO 20022 exchangeable) began.
- November 2025: coexistence was due to end; SWIFT extended support of a few MT
  messages for about one additional year — but core MT103/MT202 will no longer
  be allowed on the SWIFT network for cross-border.
- November 2026/27: final release; all payment instructions ISO 20022 only.
- Reporting messages (MT940 etc.) have no fixed cut-off; banks may keep using
  MT940 over FIN during transition.
Sources: https://www.paiementor.com/cbpr-plus-iso-20022-migration/ ;
https://de.wikipedia.org/wiki/Camt-Format
- Infrastructure adoptions: Eurosystem T2 (March 2023), CHIPS (April 2024),
  Fedwire Funds Service (July 2025), FedNow, RTP all use/used ISO 20022.
  Source: https://en.wikipedia.org/wiki/ISO_20022

## 5. Why this matters for reconciliation (ops perspective)

- ISO 20022 carries richer structured data: mandatory payer/payee structured
  fields (CBPR+), EndToEndId end-to-end, UETR (Unique End-to-end Transaction
  Reference, carried in the MT user block), structured remittance — all of which
  support higher straight-through processing and automated matching.
  Sources: https://www.paiementor.com/cbpr-plus-iso-20022-migration/ ;
  https://de.wikipedia.org/wiki/Camt-Format
- camt.053/camt.054 structured elements (EndToEndId, InstrId, ValDt, Amt,
  CdtDbtInd) map 1:1 onto the ReconForge field model (ref, amount, ccy,
  value_date, counterparty, beneficiary).
  Source: https://de.wikipedia.org/wiki/Camt-Format
